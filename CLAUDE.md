# meu-bot

- O `meu-bot` e o `meu-bot-admin-gestao` instalados em `~/Applications` são sempre o `origin/main` de agora: o hook `Stop` `scripts/hooks/rebuild-auto.sh` os reempacota (de um worktree fixo, `../meu-bot-build-main`) quando o `main` do GitHub muda. Mudança num branch ganha só `npm test` pelo hook; para vê-la na tela antes do merge, empacote à mão (`npm run dist…` de dentro do worktree, skill `rebuildar`) e lembre que o próximo merge no `main` reinstala por cima.
- Release é automática depois do merge: o agente do launchd `scripts/release-auto.mjs` (instale com `node scripts/release-auto.mjs --instalar`) solta o staging 10 min depois do último merge e promove para estável 24 h depois, se o `meu-bot-staging` deste Mac (vindo da release, não de build local) confirmou a versão. Os dois staging instalados se atualizam pelo atualizador; não os empacote à mão. Componente da máquina que muda sobe a versão no próprio PR (o CI recusa sem), e mudança visível escreve seu item em "Ainda não lançado" do `docs/CHANGELOG.md`.
- Mudança que vai virar PR nasce num worktree próprio (`git worktree add -b <branch> ../meu-bot-<nome> origin/main`), nunca trocando de branch neste checkout: outras sessões (Claude, Cursor) usam este diretório ao mesmo tempo. A skill `contribuir` diz como preparar o worktree para empacotar.
- Antes de conferir uma mudança na tela, confirme que o app instalado é o seu build: `grep -a -c <símbolo novo> ~/Applications/<app>.app/Contents/Resources/app.asar`. O hook de rebuild de outra sessão pode ter reinstalado a partir de outro branch.
- Trabalho commitado num branch sem PR: o hook `Stop` `scripts/hooks/pr-lembrete.sh` avisa ao fim da resposta; se o branch é seu, abra a PR pela skill `contribuir` sem esperar o usuário pedir.
